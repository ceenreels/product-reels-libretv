# 剧美天下国际化与地区视频源路由设计

## 状态

已获用户同意进入设计文档阶段，等待文档审阅后实施。

## 背景与目标

剧美天下目前使用中文静态界面，默认视频源固定为 `ffzy`，聚合搜索会遍历所有已配置源。该模式适合中文用户，但不适合不同语言和地区的访问者，也会把不匹配或不稳定的视频源加入请求。

本项目的目标是：

1. 根据用户偏好和浏览器区域显示合适的界面语言；
2. 根据国家/地区和内容语言选择默认视频源列表；
3. 让聚合搜索只请求当前地区允许且健康的源；
4. 保留用户手动选择和现有中文用户的兼容性；
5. 允许以后添加更多语言、地区和视频源，而不重写搜索页面；
6. 在源故障时快速回退，不让地区路由影响搜索和播放。

第一阶段明确支持：

- 简体中文（`zh-CN`）
- 繁体中文（`zh-TW`，同时覆盖 `zh-HK`）
- English（`en`，作为全球默认回退语言）

日语、韩语、西班牙语及更多国际视频源留给后续阶段；第一阶段的源注册表必须允许直接扩展。

## 非目标

- 不自动翻译视频标题、简介或演员信息；这些内容优先保持源站原文。
- 不凭空添加未经验证、未经授权或不稳定的视频接口。
- 不使用机器人、刷量、诱导点击或欺骗性跳转来增加流量。
- 不强制收集用户 IP、Cookie、密码或登录会话。
- 不因为用户所在地区而永久锁定源；用户始终可以手动覆盖自动选择。

## 现状约束

- 项目是 GitHub Pages 静态站点，前端通过 `js/api.js` 拦截 `/api/*` 请求并经公共代理访问源站。
- 目前所有界面文案直接写在 `index.html`、`player.html`、`about.html` 和 `privacy.html` 中。
- `API_SITES` 位于 `js/config.js`，只有 API 地址和名称，没有语言、地区、优先级或能力元数据。
- `handleAggregatedSearch()` 当前遍历所有 `API_SITES`，没有地区过滤。
- 用户当前源选择保存在 `localStorage.currentApiSource`。
- 首页推荐使用当前源；自定义源和聚合源目前回退到固定的 `DEFAULT_API_SOURCE`。

## 方案概览

采用“用户选择优先、浏览器区域推断、英文兜底”的客户端方案，并把源路由配置从 API 地址中抽离出来。

### 语言选择优先级

```text
用户手动选择的语言
→ localStorage 中已保存的语言
→ navigator.languages / navigator.language
→ English
```

应用启动时将最终语言写入 `<html lang>`，并通过语言字典渲染界面文本。用户切换语言后立即更新当前页面可翻译文案，并保存选择。

### 国家/地区选择优先级

```text
用户手动选择的国家/地区
→ localStorage 中已保存的国家/地区
→ 浏览器语言中的区域部分（例如 en-US、zh-TW）
→ 语言对应的全球区域组
```

浏览器区域只能作为推断，不宣称等同于真实 IP 国家。第一阶段不接入外部 IP 定位服务，以避免额外隐私、延迟和 CORS 依赖。以后若需要更准确的国家判断，应在 Cloudflare Worker/边缘层读取可信的国家代码，并把它作为可选增强，而不是替代手动选择。

## 国际化结构

新增独立的国际化模块，例如 `js/i18n/index.js` 和 `js/i18n/messages.js`：

```js
export const SUPPORTED_LOCALES = ['zh-CN', 'zh-TW', 'en'];

export const MESSAGES = {
  'zh-CN': {
    search: '视频搜索',
    recommendations: '热门推荐',
    chooseSource: '选择采集站点'
  },
  'zh-TW': {
    search: '影片搜尋',
    recommendations: '熱門推薦',
    chooseSource: '選擇影片來源'
  },
  en: {
    search: 'Search videos',
    recommendations: 'Popular',
    chooseSource: 'Choose a video source'
  }
};
```

实际实现会为所有可见 UI 文案提供键值，避免把中文文本散落在业务逻辑中。文案缺失时按以下顺序回退：完整 locale → 语言前缀 → `en` → 键名。

视频数据字段不进入 UI 字典。`vod_name`、`vod_content`、`vod_actor` 等仍显示源站提供的文字，并在卡片上保留来源徽章。

## 地区与视频源注册表

将 `API_SITES` 扩展为统一的源注册表。保留现有源的 ID，避免破坏 `localStorage` 和详情页链接：

```js
export const VIDEO_SOURCES = {
  ffzy: {
    name: '非凡影视',
    languages: ['zh-CN'],
    regions: ['CN', 'SG'],
    priority: 100,
    api: 'http://ffzy5.tv',
    capabilities: { search: true, detail: true, recommendations: true },
    enabled: true
  }
};
```

每个源至少包含：

- `name`：显示名称；
- `languages`：源内容语言；
- `regions`：适合的国家/地区代码或区域组；
- `priority`：同组内的优先级；
- `api`、`detail` 和接口能力；
- `enabled`：运营开关；
- 可选的 `adapter`/格式标识，用于非 AppleCMS 接口。

地区默认列表单独配置，不能硬编码在搜索函数里：

```js
export const REGION_SOURCE_RULES = {
  CN: ['ffzy', 'tyyszy', 'zy360', 'jisu'],
  TW: ['tyyszy', 'zy360'],
  HK: ['tyyszy', 'zy360'],
  GLOBAL_EN: []
};
```

`GLOBAL_EN` 在第一阶段可以为空，系统会显示“暂无匹配英文源”，并允许用户手动选择可用源；在加入经过验证的英文源后，只需更新注册表和规则，不改 UI 或搜索流程。

## 源路由与搜索流程

统一提供以下纯函数，供首页、设置页、推荐和聚合搜索复用：

- `resolveLocale({ storedLocale, browserLanguages })`；
- `resolveRegion({ storedRegion, locale })`；
- `getEligibleSources({ locale, region, mode })`；
- `getFallbackSources({ locale, region })`。

单源搜索流程：

1. 若用户手动选定具体源，优先使用该源；
2. 若选择“地区推荐”，使用当前地区规则中的健康源；
3. 若选择“聚合搜索”，只并行请求当前地区和语言匹配的源；
4. 若匹配源为空或全部失败，回退到同语言全球源；
5. 最后才回退到全局健康源，并在界面显示当前回退状态。

聚合结果继续使用 `source_code + vod_id` 去重，并保留来源徽章。源的临时请求失败只影响该源，不中断其他源。

推荐列表使用同一套路由规则，不再在 `custom`/`aggregated` 情况下无条件回到固定 `ffzy`。如果地区无匹配推荐源，使用缓存的上一次成功列表或显示可理解的本地化提示。

## 设置与迁移

设置面板增加：

- 界面语言；
- 国家/地区；
- 默认源模式（地区推荐、聚合、手动指定）；
- 当前使用的源列表和健康状态。

现有 `localStorage.currentApiSource` 继续有效。旧用户若没有新的地区设置，按照现有中文偏好兼容迁移：

- 已保存的具体源继续使用；
- 没有保存源时，中文浏览器默认使用 `zh-CN` 规则；
- 其他用户默认使用 English 界面和地区推荐模式。

切换语言或地区时只重置搜索/推荐视图，不清除搜索历史、播放设置或广告设置。

## SEO 与入口

第一阶段将所有静态页面补齐语言元数据，并为主要语言提供可分享入口，例如：

- `/?lang=zh-CN`
- `/?lang=zh-TW`
- `/?lang=en`

语言参数只作为入口提示，用户明确选择后以本地存储为准。每个入口需要生成对应的 `title`、`description`、Open Graph 信息和 `hreflang` 关系；默认 canonical 指向规范语言入口，避免重复内容泛滥。

由于首页内容仍由客户端 API 动态加载，不把动态搜索结果伪装成静态 SEO 页面。后续若要做可索引的影片详情页，需要另立方案，确认内容授权、数据新鲜度和构建成本。

## 隐私与合规

- 语言、地区和源偏好只保存在用户设备的 `localStorage`，不上传到本站。
- 不新增 IP 定位、指纹识别或跨站追踪。
- 第三方视频源和广告平台仍按各自隐私政策处理请求数据；隐私页需说明新增的语言/地区本地偏好。
- 新增源必须先做接口、播放、内容合规和稳定性核验，再加入公开规则。
- 不根据地区展示会违反广告平台或当地法律要求的内容；成人广告或成人内容如需保留，应单独评估年龄与地区限制。

## 错误处理与回退

- 不支持的 locale 回退到 `en`；不支持的地区回退到语言区域组。
- 源配置缺失、接口超时、JSON 格式错误或播放地址为空时，将源标记为本次请求不可用。
- 不把一次网络故障永久写入用户配置；健康结果只使用短期缓存。
- 搜索无结果时明确区分“该地区暂无匹配源”和“匹配源没有结果”。
- 详情页使用结果中的 `source_code` 请求对应源，避免跨源 ID 冲突。

## 测试与验收

新增单元测试覆盖：

1. locale 解析、语言前缀回退和未知语言回退；
2. `zh-CN`、`zh-TW`、`en-US` 的地区解析；
3. 用户手动选择覆盖自动选择并持久化；
4. 地区规则只返回匹配源，聚合搜索不请求不匹配源；
5. 匹配源全部失败时按同语言和全局顺序回退；
6. 推荐、搜索、详情使用同一 `source_code`；
7. 现有中文用户的 `currentApiSource` 迁移；
8. 静态页面含正确 `lang`、canonical、Open Graph 和 hreflang 元数据；
9. 现有广告、推荐缓存和视频播放器测试继续通过。

验收分两层：

- 本地：`npm test` 全部通过，并使用静态服务器检查中英文入口和设置切换；
- 线上：部署后核验三种语言入口、地区规则、源故障回退、推荐和播放器；不把浏览器控制不可用时的测试结果冒充线上验证。

## 分阶段交付

### 第一阶段

- 中简、繁中、English UI；
- 浏览器语言识别和手动语言/地区选择；
- 源注册表元数据；
- 中国大陆、港澳台和全球英文区域规则；
- 按地区过滤的单源/聚合搜索；
- 兼容旧的 `currentApiSource`；
- 单元测试和线上静态检查。

### 第二阶段

- 经过验证的英文、日文、韩文等视频源；
- 对应地区的推荐和搜索规则；
- 更完整的健康评分与运营配置；
- 如有必要，再评估 Cloudflare Worker 的国家代码和更细粒度入口。
